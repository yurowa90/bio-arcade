# 인수인계 절차

## 1. 사실 확인

```bash
git status -sb
git log --oneline -8
```

이번 세션에서 실행한 검증 명령과 결과(PASS 수, 종료 코드, errors)를 모은다. 실행하지 않은 검증은 '미실행'으로 둔다.

## 2. docs/PROGRESS.md 고치기

- **상태 스냅샷**: 마지막 전체 검증의 날짜·커밋·결과를 바꾼다.
- **다음 할 일(T번호)**: 끝낸 항목을 지우고, 새로 생긴 일을 다음 T번호로 우선순위에 맞는 자리에 넣는다. 남은 항목의 번호는 바꾸지 않는다. 머리의 '다음 번호'도 고친다. 진행 중인 일은 '어디까지 했고 다음 단계가 무엇인지' 한두 문장으로 적는다.
- **교사 판단이 필요한 미결 사항(M번호)**: 풀린 것은 지우고(결정은 DECISIONS로), 새로 생긴 것을 다음 M번호로 추가한다.
- **최근 작업 기록**: 맨 위에 한 줄 추가하고 5개를 넘으면 가장 오래된 줄을 지운다.
- 파일을 60줄 안팎으로 유지한다. `CLAUDE.md`가 매 세션 이 파일을 불러오기 때문이다.

## 3. docs/DECISIONS.md에 결정 남기기

이번 세션에서 규칙·수치·문구·구조를 '이렇게 하기로' 정한 것이 있으면 맨 아래에 다음 번호로 추가하고 색인 표에도 한 줄 넣는다. 결정은 내린 자리에서 바로 쓴다. 맥락, 결정, 근거(검증 수치), 검토한 대안, 영향, 관련 커밋을 적는다(형식은 그 문서 머리말).

이전 결정을 뒤집으려면 먼저 사용자에게 근거를 들어 확인한다. 뒤집으면 원래 항목을 지우지 않고 상태를 `대체됨(D-0NN)`으로 바꾼다. 교사 판단이 필요한 선택은 추측으로 정하지 않고 사용자에게 묻거나 PROGRESS의 미결 사항(M)에 올린다.

## 4. 커밋

문서만 바꿨으면 `문서: 진행 상황 갱신`처럼 따로 커밋한다. push는 사용자가 요청할 때만 한다.
